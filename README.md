# Persona Pilot Annotations

A small Streamlit app that presents a welcome screen, draws questions in a random order, and appends each submitted response to a JSONL file.

## Twin-2K participant flow

Participant IDs beginning with `0` enter the Twin-2K experiment. Each ID is
assigned a stable persona, sees its demographics and qualitative responses in
separate steps, and then answers all 44 BFI items using the combined persona.

By default the app streams the `full_persona` configuration directly from
`LLM-Digital-Twin/Twin-2K-500` on Hugging Face, selects only `pid` and
`persona_summary`, derives the demographic and qualitative sections in memory,
and caches them for the running app process. No generated Twin-2K directory is
required for deployment.

For offline use, set `TWIN2K_DATASET_PATH` to a dataset directory generated by
`create_short_personas.py` or to a JSONL export. Older generated datasets
without a separate `persona_qualitative` column remain supported.

Participant IDs beginning with `1` enter OpinionQA. The app loads
`opinionqa_sample.csv`, assigns one existing persona-question row, and never
loads the human `answer` into the participant-facing assignment. Set
`OPINIONQA_SAMPLE_PATH` to use a different CSV path.

## Run locally

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

For deployment services that expect the conventional Streamlit entry point, use
`streamlit_app.py` instead:

```powershell
streamlit run streamlit_app.py
```

When deploying on Streamlit Community Cloud, select `streamlit_app.py` as the
main file. It runs the same application as `app.py`.

Responses are written to `data/responses.jsonl`. Each line is a complete JSON object, so a successfully submitted response is retained even if the browser closes before the participant finishes.

For deployment, configure Supabase in Streamlit Secrets. When these values are
present, responses and resume checks use the `responses` table instead of the
local JSONL fallback:

```toml
[supabase]
url = "https://YOUR-PROJECT.supabase.co"
secret_key = "sb_secret_..."
```

To use another output location, set `RESULTS_PATH` before starting the app:

```powershell
$env:RESULTS_PATH = "C:\path\to\responses.jsonl"
streamlit run app.py
```

## Edit the question set

Update `questions.json`. Every item must have a unique `id`, a `question`, and a `description`:

```json
{
  "id": "unique-id",
  "question": "The question shown to the participant",
  "description": "Extra context or guidance"
}
```

## Generate persona survey responses

`generate_persona_responses.py` reads rows in this order:

1. persona
2. ID
3. question
4. question ID
5. choices
6. human answer

It copies every original column and appends the model's response. The model receives
only the persona, question, and choices; it never receives the human answer.

Set the API key for the provider you want to use:

```powershell
$env:OPENAI_API_KEY = "your-key"
# or
$env:GEMINI_API_KEY = "your-key"
```

Then run one of these commands (replace the model name if desired):

```powershell
python generate_persona_responses.py input.csv output.csv openai gpt-5.5
python generate_persona_responses.py input.csv output.csv gemini gemini-3.5-flash
```

If the CSV has a header row, add `--has-header`.

### Run with Slurm (`sbatch`)

On the cluster, create the environment once from the project directory:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-batch.txt
```

Export your API key, then submit the job from the project directory:

```bash
export OPENAI_API_KEY="your-key"
sbatch --export=ALL,INPUT_CSV=input.csv,OUTPUT_CSV=output.csv,PROVIDER=openai,MODEL=gpt-5.5 run_persona_responses.sbatch
```

For Gemini:

```bash
export GEMINI_API_KEY="your-key"
sbatch --export=ALL,INPUT_CSV=input.csv,OUTPUT_CSV=output.csv,PROVIDER=gemini,MODEL=gemini-3.5-flash run_persona_responses.sbatch
```

Add `HAS_HEADER=1` to `--export` if the CSV has a header. Slurm writes progress
to `persona-responses-JOB_ID.out` and errors to `persona-responses-JOB_ID.err`.
If your cluster uses a module-provided Python, load that module before creating
the virtual environment.

## Evaluate model responses

The evaluation script treats column 6 as the human gold answer and the final
column as the model answer. It reports:

- Exact-match fidelity: the percentage of model answers exactly equal to the
  corresponding human answers (after removing surrounding whitespace).
- Normalized Wasserstein distance: the distance between the ordered human and
  model answer distributions. Zero is an identical distribution; larger values
  mean less similar distributions.
- The same measures by question and demographic group.
- A human baseline comparing each demographic group's human distribution with
  the overall human distribution, following the supplied evaluation code.

Run:

```bash
python evaluate_persona_responses.py random_10_luna6.csv evaluations/luna6
```

Add `--has-header` if the results CSV has a header. This creates:

```text
evaluations/luna6_summary.csv
evaluations/luna6_by_question.csv
evaluations/luna6_by_demographic.csv
evaluations/luna6_human_baseline.csv
```

Model responses that do not exactly match any listed option are reported as
invalid and excluded from the Wasserstein distribution calculation. They still
count as incorrect in exact-match fidelity.
